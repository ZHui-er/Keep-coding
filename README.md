# BLE Health Demo

一个 Android 原生 BLE 穿戴设备健康数据 MVP。由于当前没有真实设备和厂商 GATT 协议，本版本使用可重复触发的 Mock 场景演示设备发现、连接、健康数据同步和 Room 持久化。

> App 中的全部设备与健康数据均为 Mock 数据，不代表真实测量结果，也不提供医疗建议。

## 已实现

- Kotlin + Jetpack Compose + Material 3。
- 首页、设备、历史三页底部导航。
- Mock 设备扫描、连接、断开和设备信息。
- 心率、血氧、步数、睡眠同步。
- Room 本地持久化，重启后保留历史。
- 十种确定性演示场景：正常、无设备、扫描超时、连接失败、连接超时、同步失败、部分数据、非法数据、存储失败、重复数据。
- 健康指标范围校验和基础单元测试。
- Repository 边界，后续可替换为真实 BLE/GATT 实现。

## 开发环境

- Android Studio（支持 Android Gradle Plugin 8.9）。
- JDK 17。
- Android SDK 35。
- Gradle 8.11.1（仓库包含 Wrapper 配置）。

## 运行

1. 使用 Android Studio 打开仓库根目录。
2. 确认 Gradle JDK 设置为 JDK 17，并安装 Android SDK 35。
3. 同步 Gradle。
4. 在 API 26 或更高版本的模拟器或真机运行 `app`。
5. 在顶部“场景”菜单选择演示场景，再进入设备页执行扫描和连接。

命令行构建：

```shell
./gradlew testDebugUnitTest assembleDebug
```

Windows：

```powershell
.\gradlew.bat testDebugUnitTest assembleDebug
```

## 扩展模块（待实现）：当日跑步训练计划

> 状态：仅完成需求分析，当前版本尚未实现。本模块不属于基础 BLE 演示范围。

### 目标

面向 18–60 岁、无已知运动禁忌的健康成年人，根据用户基本资料、昨夜睡眠时长和今日主观精力，生成一份可解释的当日跑步训练预设。

该功能定位为一般健身辅助，不提供医疗诊断、疾病治疗或专业运动处方。

### 轻量版输入

- 年龄。
- 身高。
- 体重。
- 跑步经验：零基础、偶尔跑、规律跑。
- 昨夜睡眠时长：优先使用设备同步数据，缺失时允许用户手动输入。
- 今日主观精力：精神好、一般、疲惫。
- 一次性安全确认：用户确认当前没有胸痛、眩晕、急性伤病或医生限制运动的情况。

身高和体重可用于计算 BMI，但 BMI 只作为保守的训练负荷修正因素，不作为诊断结果。CDC 将 BMI 定义为筛查指标，并建议结合其他健康信息理解结果：[CDC BMI 说明](https://www.cdc.gov/BMI/about/index.html)。

### 生成方案

轻量版采用确定性规则引擎和固定训练模板，不引入大模型：

```text
跑步经验
  → 选择基础训练模板
  → 根据睡眠和主观精力维持或降低训练等级
  → 根据 BMI 做保守的低冲击调整
  → 输出今日训练预设与调整原因
```

建议的保守规则：

- 睡眠不少于 7 小时且精力良好：保持当前经验等级的基础模板。
- 睡眠 6–7 小时或精力一般：降低一级强度并缩短主体训练。
- 睡眠少于 6 小时或主观感到疲惫：改为恢复步行、跑走结合或休息。
- BMI 位于明显偏低或偏高区间：不作诊断，优先选择低冲击和跑走结合模板。
- 任一安全确认不满足：不生成跑步训练，提示用户停止并寻求专业建议。

成年人通常建议规律获得至少 7 小时睡眠，但个人需求存在差异：[AASM/SRS 成年人睡眠时长共识](https://aasm.org/resources/pdf/pressroom/adult-sleep-duration-consensus.pdf)。WHO 建议成年人每周进行 150–300 分钟中等强度或 75–150 分钟高强度活动；该建议仅作为总体活动量参考，不能直接等同于个人跑步处方：[WHO 身体活动建议](https://www.who.int/europe/news-room/fact-sheets/item/everyday-actions-for-better-health-who-recommendations)。

### 输出内容

每份当日计划至少包含：

- 训练类型：休息、恢复步行、跑走结合或轻松跑。
- 建议总时长。
- 热身阶段。
- 主体训练及跑走比例。
- 放松阶段。
- 本次调整原因，例如“昨夜睡眠不足，已降低训练强度”。
- 安全提示和停止训练条件。

计划应保存生成时间、使用的数据快照和规则版本，确保结果可追溯。用户资料和训练计划需要独立于设备健康记录存储。

### 建议模块边界

```text
UserProfileRepository
  └── 年龄、身高、体重、跑步经验

DailyReadiness
  └── 睡眠时长、主观精力、安全确认

TrainingPlanEngine
  └── 纯 Kotlin 规则和训练模板

TrainingPlanRepository
  └── 保存当日计划与输入快照

TrainingPlanScreen
  └── 资料输入、计划展示和重新生成
```

`TrainingPlanEngine` 应保持为无 Android 依赖的纯 Kotlin 模块，以便单元测试覆盖所有规则分支。大模型即使后续接入，也只能用于自然语言解释，不参与训练强度、时长或安全决策。

### 实现复杂度

- 轻量 Mock 版本预计 4–8 小时：资料表单、规则引擎、当日计划页面、Room 表和单元测试。
- 真实产品版本还需要验证设备睡眠数据的可靠性、规则合理性、隐私处理和安全审查。

### 后续完整扩展

轻量版稳定后，可以扩展为完整输入方案：

- 训练目标：恢复活动、减脂、提升耐力。
- 今日可训练时间。
- 最近 7 天跑步次数、距离和总时长。
- 静息心率及近期变化。
- 最近一次跑步距离和配速。
- 更完整的运动禁忌与伤病筛查。
- 7 天基础计划，以及根据每日睡眠和恢复状态进行动态调整。
- 真实设备睡眠阶段、夜间醒来和恢复趋势，但不将消费级穿戴数据视为医疗诊断结果。
